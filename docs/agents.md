# Using Kagaz as an agent

Kagaz is built to be legible to an AI agent with nothing but shell access,
and to expose a purpose-built MCP server for agents that speak MCP. This
page is the contract; if you're an agent reading this to figure out how to
work with a Kagaz vault, start here.

## Two ways in

1. **Shell out to `kagaz --json`.** Every command supports `--json` with a
   stable, documented shape (see [commands.md](commands.md)). This is the
   same interface the Swift menu-bar app and the MCP server themselves use
   — nothing is held back from a shell-only agent.
2. **Speak MCP.** `kagaz mcp` runs a stdio JSON-RPC 2.0 server exposing
   `find`, `ingest_propose`, `tag`, and `resolve_for_send` as tools. Each is
   a thin wrapper returning the exact JSON shapes the CLI emits.

Either way, you are talking to the same Go core (`internal/vaultkit/`) —
there is no separate "agent mode" with different behavior or weaker
guardrails.

## What every vault teaches you about itself

A vault's own `AGENTS.md`, regenerated by `kagaz index` (or `kagaz init`) at
the vault root, is rendered from
[`docs/AGENTS.template.md`](AGENTS.template.md) combined with that vault's
`vault.yaml`. It teaches an agent the vault's actual, current:

- filename grammar and folder layout (§ [conventions-guide.md](conventions-guide.md)),
- controlled tag vocabulary,
- ready-to-run `mdfind` smart-folder queries,
- and how to call `kagaz --json` for anything the static file listing can't
  tell you (current lint status, fiscal-year context, and so on).

**Read a vault's own `AGENTS.md` before acting on it.** It is regenerated
whenever the vault's structure or vocabulary changes, so it is more current
than this page for anything vault-specific — this page documents the
mechanism and the invariants; `AGENTS.md` documents *this vault*.

## Invariants that hold regardless of how you connect

- **You cannot bypass propose → preview → approve → execute.** Every
  mutating call — CLI or MCP — previews before it commits, and requires
  explicit approval (`--yes`/`--accept-proposal`, or the MCP tool's
  confirmation argument) before touching a file. `--propose-only` (CLI) or
  the propose-only tool call (MCP) always exits/returns without mutating.
- **`resolve --for-send` / `resolve_for_send` cannot be auto-confirmed.**
  Requesting a confidential document for external handoff always returns a
  structured `confirmation_required` response instead of a path until an
  explicit confirmation is supplied, and an audit line is written either
  way. There is no argument, flag, or tool parameter that skips it. See
  [commands.md](commands.md#resolve---for-send).
- **Every mutation is reversible.** `kagaz rollback <manifest>` undoes any
  manifest a mutating call produced.
- **Nothing you do through Kagaz reaches the network**, except an explicit,
  human-run `kagaz model pull`. Classification and OCR are fully on-device;
  an agent cannot cause a document's text to leave the machine through
  normal use of these tools.
- **A vault document is never deleted.** A "move" relocates the file and
  retires the source into a staging folder inside the vault that only the
  human user empties.

## A minimal agent loop

```
kagaz find --doctype invoice --person "Alex Rao" --period FY2026 --json
kagaz ingest ~/Downloads/new-invoice.pdf --propose-only --json
# review the proposal, then:
kagaz ingest ~/Downloads/new-invoice.pdf --yes --json
kagaz lint --json
```

The same sequence over MCP calls `find`, then `ingest_propose`, then (after
the caller signals approval) whatever tool executes the accepted proposal,
with identical JSON in and out.
